# 架构（v0.1 草案）

状态：讨论稿。写于 2026-11-07。改动请走 PR。

## 一句话

开源的 AI 角色都在学怎么说话。这个项目学怎么听。

## 边界

**做**

- 一个可替换角色的实时语音对话引擎。角色 = 一份配置。
- 重点投资「倾听层」：判断该接话 / 该附和 / 该点头 / 该继续等，并把它变成角色的身体反应。
- 渲染后端可换。Live2D（2D）与 VRM（3D）走同一套抽象，同一个角色可以只有一种，也可以两种都有。

**不做**

- 不训练大模型，不训练动作模型。全部用现成开源件。
- 仓库里不放任何游戏角色素材。零 IP。
- 不做商用、不做托管服务、不做多租户。

## 链路

```
麦克风 ──► VAD/ASR ──► 倾听层 ──► LLM(人设+记忆) ──► TTS ──► 渲染驱动 ──► 画面
                        │                                        ▲
                        └──────── 表情 / 动作参数 ────────────────┘
```

倾听层是唯一新增的环节，横跨 LLM 前后两侧：

- **输入侧**：消费音频流，持续输出离散事件 `backchannel` / `turn_take` / `hold` / `nod`。MaAI 提供 turn-taking 与 backchannel 概率；这不是 VAD——VAD 只知道「有没有声音」，判断不了「这个停顿是不是说完」。
- **输出侧**：把事件映射成渲染后端的参数：点头幅度、眨眼、嘴角、眼神偏移、呼吸节奏。映射表属于角色配置，不属于引擎。

说话路径不变：LLM 出文本 → TTS 出音频 → 音频驱动口型。倾听层只在说话路径之外并行跑。

## 三态机

三态 `speaking` / `listening` / `thinking`，加两个正交修饰：`conversing`（对话窗口期内）与 `locked`（局部动作覆盖期间）。

约束：

- 任何状态切换都必须走过渡曲线，不允许瞬变。
- **barge-in**：用户开口时 `speaking → listening` 的衰减必须在 100ms 内开始。做不到这一点，整套东西会像对着机器人打电话。
- 局部覆盖（比如挥手）只锁原型切换，不缩放未覆盖关节、不改变骨骼姿态。

这一条参考了 HAST-SEC 的 `motion/base_policy.mjs`，它的三态机写得比大多数项目干净，值得读。

## 角色 = 配置

一个角色是一个目录：

```toml
# characters/<name>/character.toml
[identity]
name = "..."
persona = "persona.md"        # 人设卡
memory_namespace = "..."      # 记忆命名空间，换角色不串味

[voice]
engine = "gpt-sovits"         # 或 bert-vits2 / 其他
model = "voice.pth"

[renderer]
type = "live2d"               # 或 "vrm"
model = "model.model3.json"   # 或 "model.vrm"

[mapping]
backchannel_nod = 0.6         # 事件 → 参数，见 docs/ 里的映射表
turn_take_blink = true
```

换一个目录就换一个人。**引擎代码里不出现任何角色名。**

这条是硬约束：一旦引擎里出现「如果角色是某某」这种判断，这个项目就退化成一次性的二创工程，而不是引擎。

## 延迟预算

| 环节 | 乐观 | 悲观 |
|---|---|---|
| VAD + ASR（流式） | 150ms | 300ms |
| LLM 首字 | 300ms | 800ms |
| TTS 首包（流式） | 200ms | 400ms |
| 渲染驱动（口型 + 表情） | 100ms | 150ms |
| **合计** | **0.75s** | **1.65s** |

人自然对话的接话间隔是 200–500ms。

**结论：这条链路结构性慢半拍，压不下去。** LPM 论文自己的数字也是约 1.6s（700ms 生成 + 700ms 精修 + 180ms VAE），它靠专门训练把「像人」补回来。所以本项目不把延迟当主 KPI——**用倾听层的行为去填这半拍**：在等 LLM 的那 0.8 秒里，角色不是静止的，它在点头、在眨眼、在给出「我在听」的信号。人说话时也会有这种填充，只是我们平时不察觉。

延迟目标改为：**从用户说完到角色有第一个可见反应（不一定是说话），≤ 300ms。**

## 渲染后端抽象

渲染层只暴露三个接口：

```
mount(canvas, modelPath)
apply(state: {speaking, listening, thinking}, t: seconds)
drive({viseme, energy}, t: seconds)   // 口型
```

Live2D 与 VRM 各自实现，上层不感知。倾听层的输出只写 `state` 与参数通道，不知道底下是 2D 还是 3D。

这样 3D 可以后补：先用免费 VRM 角色（VRoid Hub 上的 CC0 模型）把 3D 后端跑通，角色模型本身以后再用 Blender 做。

## MVP 验收标准

> 你对着它连说 90 秒，不提任何问题。它的反应不像一台在等你说完的机器。

拆成可测的三条：

1. 90 秒内至少给出 4 次非语言反馈（点头 / 附和 / 表情变化），且没有一次是「说完之后才发生」。
2. 用户中途停顿 0.8 秒，角色不抢话。
3. 用户开口打断，角色 200ms 内停止发声且表情不僵。
